CypherKey — design & style guide
Implementation spec for the MV3 extension. Everything here is decided; anything not here is open.
Design system: Nocturne (bound)
Reference board: CypherKey Design Pass v2
380px popup + options page · build 0.9.4
01 · Foundation

Every surface loads the bound system and takes all colour, type, spacing, radius and shadow from its variables. Never hard-code a value the tokens already carry.

<link rel="stylesheet" href="_ds/nocturne-…/styles.css">
<script src="_ds/nocturne-…/_ds_bundle.js"></script>

Type: Inter for the wordmark only, bundled and subset to its seven letters (3 KB). Everything else takes the platform interface face — SF Pro, Segoe UI, the system grotesque — chosen to sit beside Inter, not against it. Heading token at weight 500, body at 400. Never bolder than 500; hierarchy is size and space. Inter throughout applies to cypherkey.io, which has no payload budget.

Icons: Phosphor, regular, 13–20px, on currentColor. The only bespoke glyph is the four-bar mark.

Accent — lines, marks, glows#9184d9

Accent ramp: 300 #d2cefd body text and links · 400 #b5abfc active marks · 700 #5d5294 borders · 900 #2b2741 tinted fills.

Neutral ramp: 800 #3f424d borders · 900 #292b31 insets and row hovers · 500 #9397ab all muted text · 200/300 text on tints.

The teal #0D9488 is retired from the extension — cypherkey.io only. Do not reintroduce it in product UI.

Never flood an area with the accent or any saturated fill; it is a 1px line, a mark or a glow. No pure black or white. Radii 4 / 8 / 14. Spacing 2.8 / 5.6 / 8.4 / 11.2 / 16.8 / 22.4 — a 0.70× scale, dense on purpose. Elevation is the shadow tokens, never hand-rolled.

03 · Palette — light

Same tokens, remapped on the theme root. Nothing in the markup changes.

bg #eceef8 · surface #f7f8fd
text #232532 · divider #cfd3e5
accent #5d5294 · muted #595d6c
tint fills #e7e5fe · tint borders #d2cefd

Muted text uses the darker steps here. Never carry dark-ground greys onto a light surface — inverted ramps were the most common defect in review.

04 · Contrast floor

Body text 4.5:1 against what is actually behind it; 3:1 only at headline scale. On the dark ground muted text stops at neutral-500 — never 600 or 700 for copy a user reads. Vault-row usernames, meta lines, counts and captions are all copy.

05 · Components

Compose from the system's classes. Do not build parallel components or restyle these; inline styles only for size, padding rhythm and layout.

.btn + -primary (accent outline, never filled), -secondary, -ghost, -icon, -block
.field .input label above control · .radio + .dot · .seg + .seg-opt
.card every panel and field row — radius 10 in the popup, 14 on the board
.table .tag .nav options page only · .hr exists, avoid it — prefer whitespace

States are already built in. Hover and pressed come from the accent ramp, focus is a 2px accent outline at 2px offset, disabled drops to 45%. Never leave a default browser focus ring; never restyle these per screen.

Every button and tag label carries white-space:nowrap — two-word labels wrap and spill otherwise.

06 · The mark & the Rhythm Light

The wordmark and the light are the same object. Four bars, 2px wide, 2.5px gap, heights 8 / 16 / 6 / 12, radius 1px — one keyframe, staggered.

@keyframes ck-bar { 0%,100% scaleY(.45) · 50% scaleY(1) }
1.05s ease-in-out infinite · delays 0 / .14 / .28 / .42s
ring 44px · mid ring inset 9px · pulse ring 2px
ck-pulse: scale(.6)→scale(1.2), 420ms, per keydown

A static state emits no animation declaration at all — pausing mid-keyframe squashes the first bar. Start and stop by swapping the shorthand and reapplying the delays.

Accessibility is spec. The light owns an ARIA live region announcing listening / matched / different. Under prefers-reduced-motion the bars hold still and step colour. Beside the light, always two counts — “14 keystrokes · 13 characters” — tabular numerals, never wrapped mid-phrase.

07 · Bands — semantic, off the accent
Pass ≥ 0.62 · #34D399 / text #6EE7B7
Unremarkable. On screen about a second, never announced.
Amber 0.45–0.62 · #FBBF24 / text #FCD34D
“Grey” in code and docs, “amber” in the UI. Nothing amplifies it: no filled panel, no icon, no exclamation — a line and a dot, and the copy de-escalates. Light theme #B45309 / text #92400E.
Fail < 0.45 · #E5484D / text #FCA5A5
Refused, and an email is sent. The band and a sentence — no score, no code.
08 · Voice

Plain, warm, a little playful, never smug. A limit is one sentence, never a wall. A failure says what to do next. Verbatim:

“That didn’t match your rhythm. Try again, or confirm it’s you another way.”
“That’s your rhythm. We’ll remember it — not what you typed, just how.”
“You look a little different today.” / “Type it again” · “Use a Backup Code”
“Copying doesn’t reveal it.”

Costly actions state their price in the same breath: “Sign out — clears this device. You’ll re-enrol your rhythm here.”

09 · Hard limits — breaking one means it cannot ship
X-1 The Rhythm Light is visible whenever capture runs. Restyle it, move it, make it beautiful. Do not make it subtle, collapse it into a hover state, or hide it to tidy a layout — capture then stops entirely.
Privacy No favicons, ever. Vault rows use letter marks generated locally from the entry, tinted by category.
A-4.1 Diagnostics stop at the band and a sentence. No score, ever — not on screen and not returned by the API. No raw error code in the UI either; `phantom_mismatch` is an identifier, not copy. No feature vector, key script, commitment or debug panel. Tightened 8 Sep: A-4.1 permits a score and the boards showed one, but a live number is the single piece of feedback an attacker can iterate against, and it tells an honest user nothing they can act on.
Recovery The Recovery Kit is a printed artefact. No dark grounds, no accent fills, nothing dependent on colour; the cost of using it appears twice and every value clears 4.5:1 in ink.
Platform 380px popup. No remote scripts, styles or fonts — bundle the typeface. 150 KB gzipped eager budget, 79% used. The 72% figure was measured by a check that counted only JavaScript reachable from src= — it could see neither a stylesheet nor a font, which are the two things a redesign adds most of. Corrected 8 Sep.
Scope Logins and secure notes only. No cards, no identities, no team or shared-vault surface, no mobile.
11 · As implemented — decisions the build forced

Everything below was settled while building the foundation. Where one of these disagrees with a section above, this section is the newer decision.

Nocturne is rebuilt, not bound. The boards link to _ds/nocturne-cf337738-…/styles.css and that file was never handed over, so the component layer is written from this guide. This guide is therefore the source of truth: if the code disagrees with it, the code is wrong.
Inter is the wordmark alone. Subset to C K e h p r y at 3 KB. A latin Inter for the whole UI is 30–40 KB against a budget already at 77% before any typeface. The UI face is the platform grotesque; a test fails if --ck-font ever names Inter, because a seven-glyph face asked to render a screen falls back silently.
The theme is stamped, not queried. Light is [data-theme="light"] set from JS. A media query would mean a second copy of the light palette in CSS, and two copies of a palette drift.
X-1 outranks the copy. “Listening to your rhythm” is the label and it does say capture is running, but the explicit sentence — “Your rhythm is being measured while this light is on” — stays beside it. X-1 is a hard limit and the line costs nothing.
Running and static are separate declarations. A paused ck-bar holds the frame it stopped on, which at 0% is scaleY(0.45), and the first bar renders squashed. Static states emit no animation at all.
Amber in the UI, grey in the code. Both names are live and neither is being retired: the band is grey in every API, log and test, and “amber” everywhere a person reads it.
Phosphor is not bundled. The icon web font is a remote stylesheet the MV3 policy refuses, and the whole family would dwarf the budget. Icons ship as inline SVG for the few glyphs actually used.
The score is gone from every frame. Frames 07 and 08 sketched “Amber band · 0.53” and “Fail · 0.31 · RH-04”. Neither ships, and the server is not being asked for a score to show. A number is what lets someone type, read 0.31, adjust, read 0.38 and repeat until it clears; nobody can decide how to type differently from a decimal, so it costs an honest user nothing. Unlock shows “Amber band” or “Refused” and a sentence. A test fails on any decimal or percentage reaching the screen.
Feedback conflicts with what shipped. Frame 16 shows band=grey ×3 · code=RH-02 in the payload. M2-17 attaches version and browser only, deliberately, with a test that greps the component for reachable session state. Band and code are permitted by A-4.1, so this is a change to make on purpose rather than a limit being broken.
10 · Surfaces to restyle

Fourteen popup frames plus the options page, all on the reference board:

Onboarding consent · Onboarding passphrase · Recovery Kit · Kit confirm (position ruler) · Enrolment · Unlock · Unlock amber · Unlock refused + step-up · Vault · Vault empty & no-results · Item detail · Item edit · Generator · Import · Profile · Feedback · Options page · printed Recovery Kit sheet.

Unlock is seen more than all the others combined — restyle it first. Item rows follow one pattern: a bordered card, a leading Phosphor icon in the accent, label above value, action on the right. Reveal is a round icon button, Copy stays worded, and the two are never merged.
